# Optional Turnstile comment verification

- **Status**: completed
- **Created**: 2026-09-13
- **Branch**: main
- **Scope**: apps/site, apps/comments, scripts/harness, docs

## Objective

Offer the first pilot an opt-in Turnstile verification adapter for comment
submissions, while retaining a provider-neutral default that has no external
script, CSP origin, or submission form until an operator configures it.

## Plan

- [x] Add the opt-in static form/container and provider adapter without putting
      a secret or a database dependency in the public bundle. (TC-01, TC-02,
      TC-03)
- [x] Generate exact conditional CSP origins and add enabled/omitted runtime
      contract coverage. (TC-02, TC-03, TC-04)
- [x] Document public/Worker configuration and optional-provider billing
      boundary. (TC-05)
- [x] Run focused and repository regression commands, then browser-verify the
      enabled static comment UI. (TC-06)

## Progress

### 2026-09-13

- User approved the documented optional Turnstile design after review.
- The Turnstile adapter emits only for a configured public site key; omitted
  builds remove the adapter from the static output and retain approved-comment
  reads without a submission form.
- Focused adapter contracts, enabled/omitted static builds, full typecheck,
  tests, lint, and portability scans passed. Headless Chrome inspected the
  enabled local article at desktop `1280x900` and mobile `390x844` using a
  fake public site key; both screenshots showed the static article and comment
  section without a page-render failure.
- Public-anonymous browser route evidence (no account is involved or required):
  home `/` 200, article `/2026/09/sample-report-01.html` 200, category
  `/search/label/General` 200, search `/search` 200, and unknown
  `/does-not-exist` 404 after normal trailing-slash redirects. Headless Chrome
  screenshots confirmed the home/article/category/search layouts and the 404
  state. The enabled article exposes native name, textarea, and submit controls
  without positive `tabindex` or a focus trap; the adapter uses no focus-moving
  code. The fake site key intentionally cannot complete a live challenge, and
  the focused DOM contract separately verifies callback, reset, and recoverable
  failure behavior without sending a real token to Cloudflare.
- `PUBLIC_BROWSER_ONLY=1 pnpm harness:browser` then completed against the local
  public build: all required public routes returned their expected statuses,
  keyboard focus was true, horizontal overflow was false, console errors were
  zero, and every discovered internal link plus feed/sitemap passed. The mode
  bypasses only unrelated authenticated-admin checks; it does not bypass any
  public route, script, or browser assertion.

## Decisions

- Turnstile is a selected operator integration, not a core comments contract.
- Neon remains the sole relational database; this scope adds no proxy, queue,
  database binding, storage service, or DNS record.

## Blockers

- None.

## Result

- Implemented and locally verified the optional Turnstile adapter, conditional
  static CSP/runtime output, provider-neutral token boundary, and public-only
  browser verification mode.
