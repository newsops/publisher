# WEB-003: Runtime theme presentation

- **Status**: completed
- **Created**: 2026-09-13
- **Branch**: main
- **Scope**: packages/content, packages/publication, docs

## Objective

Restore complete, responsive visual presentation to the static public release
without weakening its small JavaScript-disabled baseline or its theme-only
invalidation boundary.

## Plan

- [x] TC-01: Define complete responsive presentation rules in the built-in
      theme payloads for semantic static page slots.
- [x] TC-02: Add a publication artifact contract test while preserving the
      selected-theme-independent article HTML dependency graph.
- [x] TC-03: Run the focused contract test and static site build.
- [x] TC-04: Activate the verified static release and verify home/article at
      desktop and 390px browser widths without horizontal overflow.

## Progress

### 2026-09-13

- Reproduced on the live release in Safari desktop and Chrome DevTools at
  1440px and 390px: the selected theme loads but has one `:root` rule only.
- Added shared semantic-slot visual rules to the theme composition consumed by
  the content package, local static generator, and production publication
  worker. The focused contract test and static build pass.
- Published a new production snapshot and activated its verified static release
  on Cloudflare Pages. Chrome DevTools observed the selected theme with 32 CSS
  rules on home, article, category, and search at 1440px and 390px; each had
  keyboard focus and no horizontal overflow. The browser audit found no console
  errors or broken same-origin links. The existing unknown-route host response
  was also observed as HTTP 200 and is outside this presentation-fix scope.

## Decisions

- Keep baseline CSS as the JS-disabled readable fallback. The selected theme
  owns complete non-semantic visual layout rules through the existing
  checksum-addressed runtime asset.

## Blockers

- None.

## Result

TC-01 through TC-04 are complete. Full typecheck, build, 168-test regression,
lint, and six harness scans passed before the live release; the production
Chrome visual audit passed after activation.
