# API-001 Site-scoped Comment Moderation

- **Status**: completed
- **Created**: 2026-09-15
- **Branch**: fix/comment-site-scope-and-admin-resource-integrity
- **Scope**: apps/admin, apps/comments, docs, scripts/harness

## Objective

Keep comment moderation explicitly scoped to the selected publication so the
admin and portable comment service share one multi-site HTTP contract.

## Plan

- [x] TC-01: Thread the validated selected site through list and update
      moderation paths, then add exact upstream-path coverage for two sites.
- [x] TC-02: Preserve authentication, origin, and no-upstream-on-invalid-input
      behavior with focused rejection coverage.
- [x] TC-03: Verify an authenticated, isolated local admin against the Node
      comments adapter at desktop and mobile widths.
- [x] TC-04: Run focused and root workspace regression checks and update the
      deployment contract documentation.

## Progress

### 2026-09-15

- Created after the site-scoped comment-moderation spec passed GATE-WRITE and
  GATE-APPROVAL. The defect was reproduced without production data: the admin
  requested an unscoped path and the portable comments adapter returned 404.
- Implemented typed site-scoped moderation paths. Focused Vitest coverage
  passes for `default` and `second-publication`, including rejected invalid
  site input and no upstream call.
- With the unmodified local Node comments adapter and an isolated owner fixture,
  Chrome rendered `No pending comments.` at desktop (Chrome 1208x768 window)
  and iPhone SE (375x667). The authenticated test-account label was
  `data002-browser@example.test` in an isolated local PGlite database; no
  production account, credential, or data was used. After a reload the Console
  reported zero messages and
  `scrollWidth=375, clientWidth=375, overflow=false`.
- Added a repository-native admin icon. `GET /icon.svg` returns 200 and the
  generated document links it as the favicon, eliminating the prior first-party
  browser 404 on a fresh navigation.
- Full regression passed: `pnpm typecheck`, `pnpm test`, `pnpm build`, and
  `pnpm harness:scan`; the harness reported 191 tests across 40 files and all
  six scans passed.

## Decisions

- The selected admin site is the authoritative moderation scope; no default or
  unscoped comment route will be introduced.

## Blockers

- None.

## Result

The admin now scopes moderation reads and mutations to the selected
publication, keeps server-only authorization at the upstream boundary, and
has browser evidence against the portable Node comments adapter.
