# Lesson → Harness

세션 대화에서 사용자가 **반복한 요청·교정**을 교훈으로 채굴해, 승인 후 **레포 하네스에 강제되는 규칙**으로 institutionalize 한다. 사용자가 매번 "반복 요청들을 보편·중립으로 규칙화해줘"를 설명하지 않아도 되게 한다.

## 발동 시점

둘 중 하나면 발동(먼저 제안):

- 사용자가 "이번 세션에서 내가 반복한 요청들 교훈으로 반영해줘", "교훈 처리해줘", "규칙/스킬로 박아줘" 류 명령.
- 에이전트가 세션 중 **사용자의 반복 교정·선호**(같은 류 지적 2회+, 또는 명시적 "앞으로 ~해라/하지 마라")를 감지.

단발 1회 지시(이번만 X 해줘)는 교훈이 아니다 — 발동하지 않는다.

## 핵심 원칙: 문서가 아니라 **메커니즘**을 만든다 (비협상)

교훈의 목적은 **재발 방지**다. **수동 문서(prose 규칙)는 "내가 그 문서를 기억해 읽기"에 의존하는 가장 약한 장치 — 재발을 못 막는다.** 박제: commitlint 한글-시작 규칙이 `git-branch.md`에 문서로 있었는데도 **한 세션에 2회 위반**됐다(반대로 commitlint **게이트**는 매번 잡았다 — 메커니즘은 작동한다). **따라서 모든 교훈은 가능한 가장 강한 강제 메커니즘을 만드는 것을 기본/목표로 하고, 수동 문서는 정당화가 필요한 최후 수단이다.**

### 강제 강도 위계 (강→약, 매 교훈은 실현 가능한 **최상위** 티어를 목표)

1. **불가능하게(eliminate)** — 잘못된 행동 자체를 구조적으로 제거. 위험 함수/플래그 삭제, 타입으로 오입력 차단, footgun 제거.
2. **자동 차단(auto-catch / FAIL)** — 재발 시 **빨갛게 실패**: commit-msg/pre-push 훅, ESLint 규칙, CI 체크, 게이트 FAIL 조건, 회귀 테스트.
3. **자동 교정(auto-correct / wrap)** — 올바른 동작을 하는 스크립트/래퍼로 **수동 경로를 대체**해 손으로 틀릴 여지 제거(예: 수동 `git branch -D` 대신 MERGED 확인 후 삭제하는 `safe-cleanup`).
4. **행동 시점 능동 주입(active nudge)** — 관련 행동을 시도하는 순간 훅이 규칙을 stdout/차단으로 들이민다(`UserPromptSubmit`·`PreToolUse`·`prepare-commit-msg` 등).
5. **수동 문서(passive doc)** — **최후 수단.** 1~4가 진짜 불가능할 때만. 이때 **왜 기계화 불가인지 명시 + `[기계화 TODO]`를 규칙·PR에 박는다.**

### 재발 테스트 (필수 게이트 — 통과 못 하면 출하 금지)

교훈을 박기 전에 자문: **"내가(또는 다른 에이전트가) 다시 틀리면, 무엇이 그걸 잡는가?"**
답이 **"문서를 기억해서 읽음"**이면 **불합격** → 한 티어 위로 올라가 메커니즘을 설계한다. 답이 구체적 메커니즘(훅이 FAIL / 스크립트가 거부 / 타입이 거부)이어야 통과.

## 절차

1. **세션 채굴(mine)** — 현재 세션 대화 전체를 훑어, 사용자가 **반복했거나 명시적으로 교정·원칙화한** 항목을 후보 교훈으로 추출한다. 각 후보에 **근거(세션 내 어디서 몇 번 나왔는지)**를 단다. 1회성·작업 고유 지시는 제외.
2. **후보 제안 + 승인** — 후보 목록을 사용자에게 제시하고 승인받는다(AskUserQuestion 등). **승인된 것만** 다음 단계로.
3. **정규화** — 승인된 각 교훈을 _중립·보편_ 원칙 1개로. 사건/책임·일회성 표현 제거, 다른 표면으로 일반화. 형식: `원칙 / Why / How to apply`.
4. **메커니즘 설계 (핵심 단계)** — 각 교훈마다 위 **강제 강도 위계 1~5를 위에서부터** 검토해 **실현 가능한 최상위 티어의 메커니즘을 만든다**. **재발 테스트**를 통과해야 한다. 수동 문서로 내려갈 거면 1~4가 왜 불가능한지 한 줄로 적는다(`[기계화 TODO]` 포함).
5. **모든 접점 탐색**(부분배선 금지) — `.agents/rules/index.md`, `CLAUDE.md` 게이트, 관련 스킬(`backlog-gate-guard` GATE-\*, `post-implementation-checklist` 등), 그리고 **메커니즘 접점**: `.husky/*` 훅·`.claude/hooks/*`·`scripts/*`·`eslint`/`commitlint` 설정·테스트.
6. **작성 + 강제화** — 메커니즘(훅/스크립트/린트/테스트/게이트 FAIL)을 **실제로 구현**하고, 정본 `.agents/rules/<slug>.md`(중립, ≤80줄)에 **그 메커니즘이 무엇인지·어디 있는지** 기록한다. 문서는 메커니즘의 **설명**이지 메커니즘의 **대체**가 아니다.
7. **메커니즘 검증** — 만든 강제가 실제로 위반을 잡는지 **직접 실행해 확인**한다(훅에 나쁜 입력 → 차단 확인 등). 검증 없이 "강제했다" 선언 금지([self-verify-first]).
8. **출하** — 브랜치(워크트리 금지) → 커밋(한국어 제목) → PR → `node scripts/safe-merge.mjs <PR>`.
9. **확인** — 교훈마다 **달성한 티어 + 메커니즘 파일**을 보고한다. 티어5(문서)면 그 사유를 명시.

## 단일 출처 = 레포 (기본 sink)

정본은 **레포(`.agents/`, `CLAUDE.md`)** 다 — 지속 교훈·선호·프로젝트 사실의 **기본 저장처는 레포**다([repo-single-source.md](../../rules/repo-single-source.md)). `CLAUDE.md`와 `.agents/`는 매 세션 컨텍스트로 로드되어 메모리 없이도 적용된다.

**메모리 단독 기록 금지(이중 기록).** 개인/세션 메모리에 둘 수는 있으나 지속 항목을 메모리에만 남기지 않는다 — 메모리에 쓰면 **레포에도 같이 기록**(정본=레포). 에이전트 기본 동작이 feedback/project를 메모리에 저장하라고 유도하면 그 저장은 허용하되 레포 이중 기록을 동반한다. 새 지속 교훈은 이 스킬로 레포에 박는다.

## 트리거 (발동 누락 방지)

`.agents/skills/`는 자동발동 스킬이 아니라 **에이전트가 능동 호출**하는 절차다. 누락을 막기 위해 `UserPromptSubmit` 훅 `correction-detect.sh`가 강한 선호/원칙 신호(앞으로·하지마·지양·규칙·교훈 등)를 감지하면 이 스킬을 쓰라고 nudge(stdout)한다. 그 nudge를 보면 — 또는 스스로 반복 교정/명시 원칙을 감지하면 — **이 절차를 실행**한다.

## 안티패턴

| 안티패턴                                   | 올바른 동작                                                      |
| ------------------------------------------ | ---------------------------------------------------------------- |
| 단발 1회 지시를 교훈으로 오인              | 2회+ 반복 또는 명시적 교정/원칙만 후보로                         |
| 채굴 후보를 승인 없이 바로 반영            | 후보 목록 제시 → 사용자 승인 후에만 반영                         |
| 임시 개인 메모리에만 기록                  | 레포(.agents/CLAUDE.md)를 단일 출처로                            |
| 사건-특정·책임 문구                        | 중립·보편 원칙으로 정규화                                        |
| **문서만 추가하고 끝(가장 흔한 약점)**     | **위계 1~4의 메커니즘을 먼저 만들고, 문서는 그 설명으로만**      |
| **"재발하면 문서를 기억해 읽음"으로 안심** | **재발 테스트 통과(훅 FAIL/스크립트 거부/타입 거부)까지 올라감** |
| 강제를 "가능하면"으로 미룸                 | 메커니즘이 기본·필수, 문서는 정당화된 최후 수단                  |
| 만든 강제를 검증 안 함                     | 나쁜 입력으로 직접 실행해 차단 확인                              |
| 한 파일만 수정(부분 배선)                  | 모든 접점에 일관 반영                                            |
